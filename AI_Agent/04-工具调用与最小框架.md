## 学习目标

把模型、工具、状态与执行器拆成可单独替换的组件；理解结构化动作怎样变成真实函数调用，并能追踪一次执行失败。

## 最小框架的职责分离

```text
Model.complete(messages, schema) → 动作 JSON
Action.parse(raw)               → 结构化动作
ToolRegistry.call(name, args)   → 真实结果或结构化错误
run_agent(...)                 → 更新状态并判断继续/结束
RunResult                      → status、answer、trace
```

模型负责提出动作；执行器决定动作是否符合协议、工具是否注册、参数是否合法，然后才调用函数。工具调用的权限与业务约束由程序实现。

对应[core.py](examples/core.py)中的 `Model` 协议只规定一个方法，因此固定脚本、本地模型、其他服务都可以使用同一个执行循环。

## 工具是带契约的外部能力

一个工具至少应描述名称、用途、输入类型、返回含义与失败方式。例如 `search_notes(query: string)` 返回片段 ID、正文、来源与匹配分数。

| 设计项 | 应解决的问题 |
| --- | --- |
| 名称与描述 | 与其他工具有何差别，何时调用？ |
| 参数 Schema | 字段是否必填，类型和允许范围是什么？ |
| 结果契约 | 成功、无结果、暂时失败是否可区分？ |
| 访问范围 | 能读取哪些资料，操作归属哪个用户？ |
| 副作用 | 重试是否会重复发送、扣费或创建记录？ |
| 时限与资源 | 最长执行多久，返回大小是否有限？ |

示例仅支持必填的平面基本类型，检查额外参数、布尔值冒充数字、非有限数字和未注册工具。真实服务可用完整 JSON Schema / 数据模型校验器，并在工具内部执行范围与权限检查。

## 动作协议与原生 Tool Calling

本仓库的教学协议用以下 JSON 表示工具动作：

```json
{"kind":"tool","tool":"add","arguments":{"a":18,"b":24},"answer":""}
```

结束动作只填写回答：

```json
{"kind":"final","tool":"","arguments":{},"answer":"42"}
```

这是“模型生成 JSON、程序解析执行”的文本动作协议。各模型服务的原生 Tool Calling 还会定义工具调用 ID、专用消息角色、参数编码和多工具返回格式；接入时要由适配层保留这些字段，不能直接把本例的 `Observation` 用户消息当成通用 SDK 协议。

JSON Schema 限制结构，程序校验动作语义，工具校验业务条件。三者均通过，也只表示调用合法；答案正确性仍需证据与验收。

## 执行循环与终止状态

| 状态或事件 | 处理方式 |
| --- | --- |
| `format_error` | 返回格式反馈，消耗一轮预算后允许重试 |
| 工具 `ok=False` | 将错误作为观察返回，由模型选择修正或结束 |
| `finished` | 收到合法最终动作；任务质量仍需另外评分 |
| `step_limit` | 模型轮数耗尽，保留轨迹供调试 |
| `model_error` | 模型适配器报错，结束本次运行 |

`max_turns` 统计模型调用轮数，包含格式修正和最终回答轮。它不能中断正在阻塞的工具；网络超时、进程隔离与取消机制需要在工具适配层另外实现。

```python
from core import Tool, ToolRegistry

registry = ToolRegistry()
registry.register(Tool("add", "两个有限数求和", {"a": "number", "b": "number"},
                       lambda a, b: a + b))
print(registry.call("add", {"a": True, "b": 3}))  # 类型错误，不执行求和
```

在 `AI_Agent/examples` 中运行。全量演示见[运行说明](examples/README.md)。

## 接入真实模型

[ollama_model.py](examples/ollama_model.py)通过本地 Ollama 的 `/api/chat` 提交消息和动作 Schema，关闭流式输出，再交给同一解析器校验。使用已安装、支持所需结构化输出的本地模型：

```bash
python AI_Agent/examples/demo.py react --live --model YOUR_LOCAL_MODEL
```

本地接口请求格式依据 [Ollama Chat 文档](https://docs.ollama.com/api/chat)及[结构化输出文档](https://docs.ollama.com/capabilities/structured-outputs)。该接口是可选路径；离线测试只验证适配器请求与响应契约，不能证明某个真实模型能稳定选择工具。

## 调试时保留哪些记录

保留任务 ID、模型版本、动作、参数、观察、状态与失败位置；业务场景还应记录工具延迟、token 用量及费用。对含有凭据、私人信息的参数和返回值先脱敏，才能写入共享日志。

示例 `trace` 保存公开教学输入和观察。它不记录内部推理，也不实现密钥管理、持久化、并发工具调度或副作用重试。

## 复习与练习

1. 注册一个只读 `lookup_term` 工具，定义查询为空时的返回值。
2. 让模型请求未注册工具，观察控制器是否执行了任何未知函数。
3. 比较“最终动作已返回”和“任务经验证成功”的区别。
