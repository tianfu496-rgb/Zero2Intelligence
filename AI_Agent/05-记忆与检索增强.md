## 学习目标

分清对话状态、跨会话记忆与外部知识库；掌握检索到回答的证据链，并能把召回失败与生成失败分开定位。

## 记忆与 RAG 的分工

| 信息 | 示例 | 建议的组织方式 |
| --- | --- | --- |
| 工作记忆 | 当前问题、上一步工具结果 | 任务状态或会话消息，容量有限 |
| 情景记忆 | 某次学习任务的过程与结论 | 带时间、来源和任务 ID 的事件 |
| 语义记忆 | 经确认的术语解释、学习偏好 | 可更新的事实记录与版本 |
| 感知记忆 | 图像、音频的内容或表示 | 多模态存储及对应检索方法 |
| 外部知识库 | 仓库笔记、论文、产品文档 | 文档索引、出处与访问范围 |

Hello Agents 按工作、情景、语义与感知等角度组织记忆。实现时还要明确何时写入、如何更新、何时遗忘。把未经验证的模型猜测写成长期事实，会让错误跨会话传播。

RAG 面向检索外部资料，再据此回答；记忆面向保存与任务或用户相关的历史。两者都可能使用向量检索，但内容来源、更新方式和生命周期不同。

## 记忆的生命周期

```text
候选信息 → 验证来源与用途 → 写入带 owner/key 的记录
        → 按任务检索 → 更新或合并 → 过期/删除
```

用户身份应由应用会话绑定，不能让模型自行选择其他用户的命名空间。保存偏好时区分用户明确表达、系统推断与已经确认的事实；记录冲突时保留时间和来源，再由明确规则决定采用哪条。

[retrieval.py](examples/retrieval.py)的 `MemoryStore` 演示命名空间、覆盖更新、TTL 和删除。它只存在于进程内，重启即丢失，不等于生产中的持久化长期记忆。过期条目不参与召回；生产存储还需清理与审计策略。

## RAG 的两条流水线

### 离线索引

读取文档 → 清洗与结构保留 → 分块 → 附加来源/版本/权限元数据 → 建立索引。

分块应尽量保留标题层级、公式和代码块的完整性。块过小会缺少语境，块过大则降低匹配精度并消耗上下文。重叠不是越多越好，应按真实问题的召回表现调整。

### 在线问答

问题分析 → 召回候选 → 可选重排 → 选择证据 → 带来源回答 → 检查支持关系。

召回用于尽量找到相关资料；重排对候选进行更精细的排序。生成前过滤访问范围，生成后验证引用是否存在、引用内容是否支持结论。高相似度只说明匹配程度，不能直接作为答案置信度。

原有的[RAG 简明流程笔记](RAG%28Retrieval%20Augmented%20Generation%29检索增强生成.md)继续保留，可用作速查。

## 检索方法与取舍

| 方法 | 优势 | 常见短板 |
| --- | --- | --- |
| TF-IDF / BM25 | 术语、名称、代码标识符匹配直观 | 同义改写和隐含语义可能漏召回 |
| 稠密向量 | 用模型表示语义，支持近义查询 | 对专有名词、版本差异未必敏感 |
| 混合召回 | 同时覆盖词面与语义信号 | 需处理分数不可直接比较的问题 |
| 交叉编码器重排 | 同时阅读问题与候选片段 | 对大量候选逐项计算成本较高 |

常用的向量相似度是余弦相似度：

```math
\mathrm{sim}(q,d)=\frac{q^\top d}{\lVert q\rVert_2\lVert d\rVert_2}
```

零向量的分母为零，应在实现中处理。Embedding 模型改变后通常需要重新编码索引；问题向量与文档向量必须处在兼容的表示空间。

## 最小可运行检索实现

[retrieval.py](examples/retrieval.py)用英文词和中文单字构造 TF-IDF 向量，以余弦相似度排序。文档带标题时，使用“正文相似度 × 0.75 + 标题相似度 × 0.25”的字段加权分数，使短标题的任务信息更容易被利用；权重只是教学设置，实际应在验证集调整。它没有调用 Embedding 服务或向量数据库，是便于理解和对照的词面基线。

```python
from retrieval import Document, Retriever

docs = [Document("rag", "RAG 先检索资料，再根据证据生成回答。", "rag.md"),
        Document("tool", "工具调用由执行器校验参数后执行。", "tools.md")]
for doc, score in Retriever(docs).search("RAG", top_k=1):
    print(doc.id, doc.source, round(score, 3))
```

在 `AI_Agent/examples` 中运行。中文单字会匹配到常见字，因此该基线容易产生弱相关结果；没有词面重叠时返回空列表，有重叠也不保证资料足够回答。

## 从固定 RAG 到 Agentic RAG

固定 RAG 每次执行预定检索流程。Agentic RAG 允许模型根据中间证据选择是否检索、重写问题、换数据源或继续追问。

引入动态检索前应有固定基线与真实问题集。为每次新增检索记录“缺少什么信息、找到了什么、为何仍需下一次”，并限制总查询数。引用与文档权限依然由应用验证。

## 分层评估

| 层次 | 要检查的内容 |
| --- | --- |
| 索引 | 目标文档是否进入索引，版本是否正确，公式是否被切断 |
| 召回 | 人工标注的相关片段是否出现在前 k 个结果中 |
| 重排 | 真正能支持问题的资料是否排在预算内 |
| 生成 | 是否回答问题，引用是否准确，是否增加资料没有的结论 |
| 拒答 | 资料不足时是否停止推断，是否指出缺失信息 |

## 复习与练习

1. 给检索示例加入同义表达，观察词面检索的漏召回。
2. 对比按字数分块与按标题分块，记录公式、代码块完整性。
3. 为过期笔记设计版本过滤，不要仅靠向量相似度选择最新事实。
