## 学习目标

分清推理时控制与参数训练，理解 SFT、奖励和 GRPO 的作用，知道训练数据中的环境观察与模型动作应如何区分。

## 从提示与工具优化走向参数优化

在训练之前，先确认错误发生在哪里：工具描述含糊、索引缺失、上下文遗漏、执行器不正确，这些问题通常应先在系统层修复。

当任务与工具契约较稳定、已有代表性的轨迹和验收标准时，可以评估训练模型是否有收益。训练目标必须对应真实行为，避免只优化输出风格而忽视任务结果。

| 方法 | 主要改变什么 | 需要什么 |
| --- | --- | --- |
| 提示与上下文调整 | 当前输入与控制方式 | 错误分析和回归集 |
| SFT | 模型参数，使其模仿示范输出 | 高质量指令、回答或工具轨迹 |
| 偏好优化 | 模型参数，使其偏向更好输出 | 可靠的偏好信号或成对比较 |
| Agentic RL | 多步交互策略的参数 | 可运行环境、奖励与采样轨迹 |

这些方法可组合，没有要求所有任务必须依次经历每一种训练阶段。

## SFT：学习格式与示范行为

SFT 对期望输出 token 最大化条件似然。多轮工具轨迹中，通常只对模型应生成的部分计算监督损失，环境返回的观察不作为模型应模仿的动作。

```math
\mathcal{L}_{\mathrm{SFT}}(\theta)
=-\sum_{t\in\mathcal{I}_{\mathrm{assistant}}}
\log P_\theta(y_t\mid x,y_{<t})
```

其中 $`\mathcal{I}_{\mathrm{assistant}}`$ 是参与训练的助手输出位置集合。模板、工具调用序列化和 loss mask 要与数据实现一致。

数据可包含：问题、允许的工具描述、模型动作、环境观察、最终产物、结果标签。把失败轨迹修正后再作为示范，或单独用于评估；不要把程序异常误写成正确操作。

LoRA 等参数高效微调方法改变可训练参数的组织方式，可减少某些训练资源开销，但仍需要处理数据质量、验证集与过拟合。

## Agentic RL：对交互轨迹给出反馈

轨迹包含多步观察和行动：当前信息 → 工具选择 → 工具结果 → 下一步 → 最终交付。优化目标是提高期望累计回报：

```math
J(\theta)=\mathbb{E}_{\tau\sim\pi_\theta}
\left[\sum_{t=0}^{T-1}\gamma^t r_t\right]
```

奖励可以来自可执行测试、答案判定、业务约束和成本。只有终局奖励时，中间步骤归因可能困难；加入过程奖励时，也要避免奖励某种表面动作而诱导无效调用。

### 奖励设计的一个例子

对“基于笔记回答问题”可以分别检查：答案是否正确、关键结论是否被证据支持、引用是否指向真实片段、工具调用是否超预算。先保持各项指标独立可见，再决定如何组合奖励。

只奖励“引用数量”可能鼓励堆积无关来源；只奖励“回答长度短”可能鼓励省略必要条件。训练后要在独立任务中检查这些投机行为。

## GRPO 的组内相对比较

[DeepSeekMath](https://arxiv.org/abs/2402.03300)介绍的 GRPO 从同一问题采样一组候选，用组内奖励构造相对优势，避免依赖与 PPO 相同形式的独立价值模型。

一个便于理解的组内标准化写法是：

```math
\hat A_i=\frac{R_i-\bar R}{\sigma_R+\varepsilon},
\qquad \bar R=\frac{1}{G}\sum_{j=1}^{G}R_j
```

这是优势估计的简化示意，不是完整 GRPO 损失。实际训练还涉及 token/序列粒度、策略比率、裁剪与可能的 KL 正则；不同实现对标准差和归一化的处理也可能不同。

当组内奖励全部相同时，相对信号可能退化。应检查采样多样性、题目难度和奖励分布，不能只看平均奖励上升。

## 一次可复现的训练实验

1. 固定任务、工具版本、环境状态与资源预算。
2. 按任务来源划分训练、验证和测试集，防止同一题目改写泄漏。
3. 先运行未训练基线，再按需要做 SFT 与 RL。
4. 保存模型、数据版本、采样配置、奖励定义和训练日志。
5. 用任务成功率、工具正确性、成本和异常恢复评估。
6. 在保留测试集上比较，确认改进没有依赖奖励规则的漏洞。

本仓库代码不包含参数训练器或 GPU 训练脚本。小型离线回归集用于理解控制与评分逻辑；实际 SFT/GRPO 实验可从本章上游教程的固定版本代码开始，单独准备依赖和算力。
