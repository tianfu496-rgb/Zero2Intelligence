## 学习目标

把“能运行一次”转为可重复的评估过程；分别检查工具、检索、任务结果与成本，能够根据失败轨迹决定修改哪一层。

## 先定义任务与成功条件

同一模型在不同工具、数据与预算下会表现不同。评估记录应包括问题集、模型标识、提示词版本、工具版本、检索配置、随机设置与最大轮数。

| 层次 | 样例问题 | 可检查的内容 |
| --- | --- | --- |
| 工具选择 | 应该计算还是检索？ | 工具名、参数值、无需调用时是否克制 |
| 检索 | 能否找到含答案的片段？ | 相关片段召回、版本与权限过滤 |
| 任务结果 | 是否交付满足约束的答案？ | 正确性、覆盖、来源支持、拒答 |
| 执行鲁棒性 | 失败后能否合理恢复？ | 解析错误、超时、重复动作、预算停止 |
| 成本 | 达成同一结果耗费多少？ | 调用数、token、延迟、费用 |

执行器的 `finished` 只代表收到了合法最终动作。评估器仍要判断产物是否合格。

## 指标与解释范围

```math
\mathrm{SuccessRate}=\frac{\sum_{i=1}^{N}\mathbf{1}[\text{任务 }i\text{ 达标}]}{N}
```

任务成功率应配合样本数和任务分布报告。随机任务可重复运行并报告波动。引用存在率和证据支持率要分开：一个 URL 确实存在，也可能与结论无关。

对工具参数使用规则或结构化比较，对可执行任务使用测试；开放回答可采用清晰量表与人工/模型评审。LLM Judge 可能受回答风格、顺序和自身能力影响，应抽样人工核对，并避免把正确答案直接泄漏给被测 Agent。

## 理解教程中的评估基准

Hello Agents 以 BFCL、GAIA 等基准介绍评估方式。阅读排行榜时核对具体版本、工具权限、执行预算和评测设置，避免把不同配置的数字直接比较。

| 基准方向 | 能帮助检查什么 | 不足以单独证明什么 |
| --- | --- | --- |
| [BFCL：函数调用](https://gorilla.cs.berkeley.edu/leaderboard.html) | 工具选择、参数与调用结构 | 自己业务中的完整任务成功率 |
| [GAIA：综合助手任务](https://huggingface.co/gaia-benchmark) | 多步信息获取与工具协作 | 所有领域都可靠，或成本可接受 |
| 自建笔记问题集 | 本仓库知识覆盖与引用支持 | 其他数据源或复杂环境中的泛化 |

原始入口见上游本章的基准介绍及参考文献；使用官方评测器时锁定对应数据与代码版本。

## 本仓库的可运行评估

[evaluate.py](examples/evaluate.py)从[样例集](examples/eval_cases.json)读取问题，调用确定性的“检索 → 摘录”策略，再由独立评分代码检查来源召回与无证据拒答。

```bash
python AI_Agent/examples/evaluate.py
python -m unittest discover -s AI_Agent/examples -p "test_*.py" -v
```

从仓库根目录执行。评估输出 `mode=offline_extractive_regression`，结果仅代表三个小型离线回归案例，不是 BFCL、GAIA 或真实 LLM 的成绩。

[test_examples.py](examples/test_examples.py)覆盖格式错误恢复、未知工具、错误参数、工具异常、轮数上限、记忆隔离与过期、原子证据预算、模型接口契约等边界。

## 按轨迹定位错误

| 现象 | 应先检查的证据 | 可能的修复 |
| --- | --- | --- |
| JSON 无法解析 | 原始响应与动作 Schema | 收紧结构、反馈格式错误 |
| 工具参数错误 | 参数与其来源片段 | 改进描述、校验范围或补充输入 |
| 回答无依据 | 召回、选入上下文、最终引用 | 补索引、调整检索或说明资料不足 |
| 调用不停重复 | 连续动作与状态变化 | 限轮数、识别无进展、修正规划 |
| 反思后仍错误 | 审查标准与修改记录 | 加入独立检查，保留未解决状态 |
| 多角色互相等待 | 任务状态与交接记录 | 明确主责、超时和失败返回 |

修改时尽量一次改变一个因素，在相同问题集上比较，才能确定收益来自哪里。

## 与可靠性直接相关的工程边界

- 读写权限在工具执行层实现；模型生成的角色、路径或用户 ID 不能自动取得访问权。
- 外部资料中的指令视为数据；来源标签有帮助，但不能代替权限限制。
- 只对适合重试的失败进行有限重试；有副作用的操作要有幂等与状态查询。
- 给循环、网络请求、输出大小分别设置预算；轮数限制无法中断阻塞工具。
- 保存可以解释故障的轨迹，对共享日志中的私人数据和凭据脱敏。

## 复习与练习

1. 增加一个“检索到资料，但资料无法支持问题”的案例，补充支持关系评分。
2. 换真实模型后固定问题集和预算，重复运行，记录波动及工具调用数。
3. 将词面检索替换为向量检索时，同时比较召回质量、任务结果与成本。
