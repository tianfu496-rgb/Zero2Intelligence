## 检测任务与输出

图像检测回答“有哪些目标、分别在哪里”，通常输出类别、边界框和置信度。同一幅图像可能包含多个实例；分类结果不能直接替代检测框。

```text
图像 → Backbone → 多尺度特征或查询交互 → 类别与边界框 → 按配置后处理
```

本章先建立 IoU、NMS、PR 和 AP 的共同语言，再理解 R-CNN 系列、YOLO、SSD，最后衔接 DETR 路线和近期实时检测模型。

## 定位、后处理与评价

### Sliding Window

最早期目标检测思想：

```text
不同大小窗口
       ↓
逐位置滑动
       ↓
分类器判断
       ↓
得到目标位置
```

问题：

- 计算量大
- 不同尺度需要大量窗口
- 效率低

### Two-stage vs One-stage

|          | Two-stage                | One-stage      |
| -------- | ------------------------ | -------------- |
| 代表     | Faster R-CNN             | YOLO、SSD      |
| 流程     | Proposal → Detection     | 直接 Detection |
| 速度     | 通常较慢                 | 通常较快       |
| 结构     | 较复杂                   | 较简单         |
| 核心优势 | 将候选区域与识别分开处理 | 端到端直接预测 |

### IoU

Intersection over Union：

```math
\mathrm{IoU}=\frac{|A\cap B|}{|A\cup B|}
```

其中：

- $`A`$：预测框
- $`B`$：Ground Truth

范围：

```math
0\le\mathrm{IoU}\le1
```

### NMS

NMS：

> Non-Maximum Suppression

目标：

> **删除同一个目标产生的重复 Bounding Boxes。**

流程：

```text
所有预测框
 ↓
按照 Confidence 排序
 ↓
选择最高分框
 ↓
删除 IoU > threshold 的框
 ↓
继续处理
```

伪代码：

```python
while boxes:
    best = highest_score_box()
    keep(best)

    boxes = [
        box for box in boxes
        if IoU(box, best) < threshold
    ]
```

### Precision

```math
\mathrm{Precision}=\frac{TP}{TP+FP}
```

含义：

> **预测为正的样本中，有多少是真的。**

### Recall

```math
\mathrm{Recall}=\frac{TP}{TP+FN}
```

含义：

> **真实正样本中，有多少被检测出来。**

### Precision-Recall

改变 confidence threshold：

```text
Threshold 高
    ↓
预测更严格
    ↓
Precision ↑
Recall ↓
```

通常：

> Precision 和 Recall 存在 trade-off。

### AP

AP：

> Average Precision

核心思想：

> **计算 Precision-Recall 曲线下面积。**

```math
AP=\int_0^1 P(R)\,dR
```

实际实现通常采用离散形式。

### mAP

如果有 $`C`$ 个类别：

```math
mAP=\frac1C\sum_{c=1}^{C}AP_c
```

注意：

> mAP 的具体定义与评测协议有关，例如 IoU 阈值和 AP 计算方式。

## 经典检测模型

### R-CNN

R-CNN：

> Regions with CNN features

流程：

```text
Image
 ↓
Selective Search
 ↓
Region Proposals
 ↓
CNN
 ↓
Feature
 ↓
SVM Classification
 ↓
Bounding Box Regression
```

问题：

> 每个 Region 都单独进行 CNN，计算重复严重。

### Fast R-CNN

改进：

> **整张图只进行一次 CNN。**

流程：

```text
Image
 ↓
CNN
 ↓
Feature Map
 ↓
RoI Pooling
 ↓
Classification + BBox Regression
```

优点：

> 比 R-CNN 快很多。

### Faster R-CNN

进一步加入：

> **RPN（Region Proposal Network）**

流程：

```text
Image
 ↓
Backbone CNN
 ↓
Feature Map
 ↓
RPN
 ↓
Region Proposals
 ↓
RoI Pooling / RoI Align
 ↓
Classification + BBox Regression
```

核心：

> **让候选区域生成也由神经网络完成。**

### YOLO

YOLO：

> You Only Look Once

核心思想：

> **将目标检测作为一个整体回归问题。**

基本：

```text
Image
 ↓
CNN
 ↓
Feature Map
 ↓
Bounding Box + Class
```

特点：

- 单阶段
- 速度快
- 适合实时检测

### SSD

SSD：

> Single Shot MultiBox Detector

特点：

> 在多个尺度的 Feature Maps 上进行检测。

```text
Backbone
 ├── Feature Map 1 → Detection
 ├── Feature Map 2 → Detection
 ├── Feature Map 3 → Detection
 └── ...
```

因此可以处理不同大小的目标。

## DETR 与近期实时检测模型

### DETR：从候选框到集合预测

DETR 使用一组目标查询预测目标集合，并在训练中匹配预测与真实目标，使读者可以从“生成候选框再筛选”的思路转向集合预测。它是理解后续检测 Transformer 的重要起点。见 [DETR 官方实现](https://github.com/facebookresearch/detr)。

### 近期模型速览

资料核对日期：**2026-10-19**。

| 模型与版本 | 主要思路 | 应关注的学习点 | 原始资料 |
| --- | --- | --- | --- |
| DEIMv2 · 2025 | 将 DINOv3 的表示能力用于实时检测，并提供不同规模的模型 | 预训练骨干、蒸馏与检测框架如何配合；各变体使用的骨干不同 | [官方代码与配置](https://github.com/Intellindust-AI-Lab/DEIMv2) |
| Ultralytics YOLO26 · 2026 | 实时视觉模型家族，提供端到端检测分支及轻量检测头设计 | 端到端分支可省去 NMS；模型家族名称、具体任务和推理分支需要分开确认 | [官方模型文档](https://docs.ultralytics.com/models/yolo26/) |

### 如何比较检测器

先固定数据集、类别定义、输入尺寸和 AP 计算协议，再比较速度。延迟还受到硬件、精度格式、推理后端、批大小及是否包含预处理/NMS 的影响；论文中的“实时”不直接等于本机端到端速度。

理解传统 NMS 仍然有价值，但不能据此假定所有新检测模型都需要相同后处理。
